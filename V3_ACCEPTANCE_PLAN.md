## Gate 0 and matched post-P1 run

1. Export the verified v2.1 revision into staging. Keep the live workspace untouched. Record revision/tree, clean or dirty state, exact CLI commands/exit codes, clock, CPU/memory, storage, OS, Python, SQLite, Codex version/hash, provider/auth mode, actual model and effort, policy limits and background load. Keep credentials and raw OAuth state private. Pin identical numerical input specs, scoring rules, model profiles, concurrency, budgets, instrumentation, start conditions and fault schedule for the post-P1 comparison. Record exact hashes of all comparison inputs.
2. Use `bin/gx-p0 start --state "$STATE" --run-key "$KEY" --spec "$SPEC"` for independent numerical `science_grid@2` Runs. Drive them together with `bin/gx-p0 run --state "$STATE" --timeout "$SECONDS"`. Obtain read-only operator state with `bin/gx-p0 status --state "$STATE"`. Exercise real provider-backed Root turns through the official Codex App Server, with simultaneous work by at least two distinct Roots observed. Keep enough bounded work queued for at least 7,200 elapsed seconds on **each** revision. A CLI timeout or early terminal Run triggers inspection of actual progress. Count wall time only during execution of the workload and document waits and outages. Persist each bounded spec and its original budget and stop at its limit.
3. Save workload start/end UTC and monotonic elapsed, status samples, native turn/usage receipts, Job/Artifact references and file digests, CLI/fault logs and metrics. Use `GX_METRICS_FILE` with the same instrumentation and location class on each side. Report errors, missing samples and provider waits explicitly. Count unique completed Turns and accepted submissions or decisions per elapsed hour, plus valid completed Jobs per hour. Derive true overlap from recorded native turn start/end times by distinct Root; report peak and time distribution. Simultaneous budget reservations alone demonstrate admitted exposure.
4. Use READY→claim times per actual Attempt or readiness episode for queue wait. Distinguish unclaimed/censored tasks, transaction latency and lock acquisition. Calculate `n`, p50/p95/p99 and maximum from raw `p0_dispatch`, `p0_callback` and `db_transaction` rows. Group callbacks by operation and exclude wait time from interpretations of hook CPU cost. Report tokens by actual meter confidence and run, successful and failed Job outcomes, duplicate launches, replays, failed Attempts, recovered original receipts and time to next useful outcome after recovery. Preserve authorized pauses and provider delays in the raw distributions. When a class has no observations, report its count and the absence of an estimate. [Measurement emitters](gx-h/gx_core/metrics.py) · [Frozen read-only audit](acceptance/v21_long_audit.py)
5. Run the same workload from fresh matched state after P1 and compare levels, absolute/relative changes, denominators and per-case behavior. Before viewing post-change results, record any agreed performance tolerance and measurement variability with the workload spec. In its absence report every adverse difference; a material or unexplained slowdown, an unmatched workload, missing instrumentation or inadequate overlap leaves performance acceptance open. Correctness comparisons have zero allowance for a crossed fence, duplicated Job/charge, broken pin, corrupt Artifact or lost result. Model-dependent decisions can vary. Independently recompute submitted numerical observations/evaluation thresholds and check the same scientific invariants on both sides.

The v2.1 16m02.729s loopback run, its 80.544s frozen replay and the single 7.137s OAuth smoke are separate historical observations. Gate 0 requires a new two-hour multi-Root real-model receipt before changing hook call sites, `_claim`, Root tool wiring or dispatch behavior. If environment or credentials block the real run, record `BLOCKED` with actual evidence. Loader-only P0 work can proceed in isolation. Advancing into P1 requires the Gate 0 evidence and the loader gate. [Frozen acceptance](V21_ACCEPTANCE_REPORT.md) · [Long-run report](V21_LONG_RUN_REPORT.md)

The live acquisition uses [the timed workload](acceptance/v3/performance/run_workload.py). Its [Gate 0 environment](acceptance/v3/performance/gate0/environment.json) records the open-loop arrival offsets, frozen model/effort, capacity and comparison thresholds. Report the duration of active native work, demand waiting for admission, and genuinely idle arrival gaps alongside wall-clock span. These arrival intervals define the offered load; assign the same workload in the candidate.

## Phase tests and business observations

The case groups below specify acceptance behavior. Each phase report must name the actual implemented test, command, exit status, immutable source revision and raw evidence path for every pass. Where implementation names may change, the public operation and existing owner define the contract.

| Phase and case | Entry or existing owner | Required observation |
|---|---|---|
| P0 manifest, approval and digest | Operator install root → strict parser → resolver → versioned loader | Valid package loads. Malformed/unknown fields, incompatible GX/API, missing or unapproved package and stale digest reject before any import side effect. Use a filesystem import canary and verify its absence on each rejection. Check a transitive dependency as well as the requested package. |
| P0 resolver and module isolation | Loader bootstrap and example package factory | Shuffle dependencies, compare deterministic order and closure, and inspect the cycle path and missing-dependency diagnostic. In one PID load two versions of the same ID with nested relative imports, separate mutable globals, distinct ID/version/digest namespaces and identical `sys.path` before/after. A failed import/register removes only its namespace/contributions. Successful `register(ctx)` occurs once per version in one bootstrap. Mutation after freeze fails. |
| P0 legacy and failure scope | `bin/gx-p0 status` and cold `run` on copied v2.1 workspace | Start without plugin metadata. Compare old Workflow/Capability pins, jobs, submissions and original charges. An unavailable or failing installed plugin leaves unaffected Runs and read-only status usable. |
| P1 real migration | Public keyed Grid `start`/`run` plus `orchestration/{registry,service,hooks}.py`, `p0/{roots,driver}.py` | Record package digest, `register(ctx)` call and declared tools. Prove actual Root dynamic callbacks use the selected version and run through to an accepted product. Cross-reference all 13 hook call sites, five P0 science modules and real call paths. Check generic core import edges and allowed imports in the installed plugin. Verify canonical Workflow and Capability pins against the old installation. |
| P1 transaction and execution | Hook methods; `capabilities/{manifest,registry,shipped}.py`, Job/Artifact/Evaluation owners | Roll back a rejected hook and verify its writes roll back with the caller's transaction. Read-only hook calls require no idempotency tokens. Exercise existing receipt paths on repeated side effects. Verify the plugin receives named operations, no raw DB handles; external execution occurs after transaction. Resolve canonical Capability bundle, launch real local numerical Job, reproduce its Artifact hash and resulting Evaluation with the correct Run, Task and Attempt. |
| P1 dispatch order and continuation | `p0/roots.py::Roots._claim`, `p0/driver.py`, `p0/team_admission.py` | Instrument dependency, provider, team and scheduler denials separately. Denial creates zero hook calls/leases. Successful claim invokes one hook after capacity and before Lease/Attempt; false return creates no lease. Check expiry and recovery with original fence. Measure stalled retries over time and show wait/backoff behavior. Repeat cold on the old pinned run and complete matched post-P1 live measurement. |
| P2 independent plugin | Separately installed package; official App Server dynamic callback; `p0/compute.py`, Job and Artifact services | Diff kernel and prove installation alone adds a Tool plus a canonical Capability or a real Evaluator; no Grid dependency. Discover contribution and call it from its intended Root. Exercise stale Attempt and cross-Run denial, actual Job completion, artifact byte hash, result and receipt. Remove installed package on a copy; its dependent Run blocks and an unrelated Run progresses. |
| P3 composition | Public `start` twice with distinct keys in one workspace/process, then `run` and cold reopen | Capture plugin ID/version/digest/API, existing Workflow identity/digest, Capability manifest refs, resolved dependency closure, composition hash. Two versions remain isolated in hooks, tools, globals and capability references. Existing Run retains exact pins after a new installation and version selection in the new Run. Restart rebinds both correctly. A missing exact pin blocks only the dependent Run. Public status remains readable. |
| P3 rollback and compatibility | Copy of GX DB + Artifact store + Job sidecars + private Codex state, old and new public executables | Record original SHA-256s and native/Job receipts after quiescence, migrate the copy, resume, restore previous complete snapshot at same paths, cold reopen, and run again. Match exact previous pins and composition. Legacy Run without plugin metadata retains historical Workflow/Capability pins. Check DB integrity and foreign keys, output hashes, budget settlement and duplicate paid work. [Frozen rollback method](V21_ROLLBACK_REPORT.md) |

Review each phase diff against the source audit. Check `p0/driver.py`, Coordinator/Outbox, native Root delivery, budgets, leases, tasks, jobs, registry/governance, artifacts and evaluations still own their existing business operation. Trace actual call or storage for each migrated surface. Inspect the separate Node plugin host. Installing a plugin must add no competing Job or Workflow registry, event bus, plugin worker process, lifecycle/health scheduler or grants machinery.
