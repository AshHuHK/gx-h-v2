## Hook calls and transaction boundaries

`gx_core/orchestration/hooks.py:98` defines **12 callable fields and two boolean fields**. There are 15 function-invocation expressions at the v2.1 core boundaries. The table covers 13 operational contexts. It distinguishes the two Task-context consumers, shows both research-start paths and both replan invocations, then records the two policy reads and returned tool callbacks below. The `prepare_job` call goes through a local variable. Searching only for `.prepare_job(` misses it.

SQLite connections use autocommit. The outermost `store.transaction` takes `BEGIN IMMEDIATE`, nested calls use savepoints and resource cleanup follows transaction completion (`gx_core/persistence/store.py:502`). “Outside” describes the normal product caller at entry. Legacy hooks can take their own transactions. “Inside” means caller-owned writer on the same connection. The table describes accepted legacy behavior, including side effects that need to move when migrating external plugin hooks.

## Claim, wait, delivery and recovery

`Driver.passes` drains compute proposals, human input and deliveries, reconciles outstanding Jobs, drives the existing reactor, then selects READY/CLAIMED/RUNNING Tasks (`p0/driver.py:290–374`). `p0/coordinator.py:137` advances each workspace Run generator on one connection. It can resume a partially created Run and backs off per Run for transport failures. The shared outer loop sleeps up to 35 ms. Waiting-for-review and capacity refusals skip the current dispatch without setting the interrupted-turn backoff; consequently an unclaimed READY task can revisit the same hook on successive passes. Single-run idle delay, outbox error backoff, provider capacity backoff and task/Job waits are distinct paths.

`p0/roots.py:377–435` first restores the exact previous Root/lease for CLAIMED or RUNNING work, protects external waits/live attempts and fences an expired one through `TeamService.recover_failed_attempt`. For a fresh Task it checks dependencies, state and consumed attempts, invokes provider admission, calls the workflow hook, rereads the Task, checks team capacity, calls `scheduling/dispatch.py:973`, issues the lease and records Task/Root/attempt/brief in one writer. `team_admission.claim_capacity` accounts for run/team/workspace capacity and unavailable tasks. Successful `_claim` and `_new_row` complete before official thread materialization or turn delivery. Preserve the original-lease recovery branch when changing fresh admission order.

The existing `science_refresh_v2.prepare_dispatch` is more than a predicate. It routes old Grid and geometry by input/version. On a changed criterion, `p0/science_refresh.py:39–82` registers derived hypotheses, publishes a revised proposal/evidence, and may reevaluate original observations. `p0/science.py:57` can invoke the optional Node scorer. The decision branch may create and bind a replacement reviewer and add `task_deps` before returning false (`p0/science_refresh_v2.py:30–66`); removing it could strand the decision. The migration must preserve these outcomes through existing durable owners, keeping calculation, external invocation and artifact publication away from a new transaction-bound dispatch hook. Recheck state/dependencies before lease issuance if a prepared operation changes them. The workflow’s prospective evaluation also freezes the criterion and verifies control scores (`p0/science.py:82–125`). Gate 0 and the performance comparison control when this path can change.

`p0/root_delivery.py:293,323,400,453,473,837,890` owns binding, reservation, prepared delivery, native acknowledgement, metering, reconciliation and transport. It journals the event/text hash and reservation before a native RPC. A lost response is reconciled against the original official history before resending. `p0/roots.py:943` wakes only the terminal Job’s original Task/lease with `wake:<lease>:<job>`; it can replay an acknowledged receipt after ownership ended. `jobs/service.py:1103` enqueues the `job.terminal` trigger and calls `waits.terminal_job` in the terminal transition’s transaction. `orchestration/reactor.py:241,313,396` consumes the existing trigger, and the driver polls/wakes the waiting Root. These pieces already supply Job completion and workflow notification.
