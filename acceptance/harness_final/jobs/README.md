# Cross-seat Job identity and delivery

New ordinary Goals carry the `gx.harness/3` contract. Each receiving node must have an active grant, compatible prospective conditions, the same named inputs, method, provider, executable, weights, parameters, effective seed, runtime and side-data pins. A shared Job retains its original reservation and publisher. Each subscribing node stores its own operation key and receives its own settlement and next-decision brief carrying the same physical Job and artifact. Unknown randomness, unavailable side-data pins, isolated seats and independent repetitions have separate identities. Cross-seat sharing is currently limited to the same Run-wide original inputs. Derived or nonpublic inputs stay within the owning branch. A mutable dataset without a byte pin requires fresh computation.

The fixtures use the ordinary research command, native Goal callbacks and real local CPU processes. Researchers are scripted to make the event interleavings reproducible. The lost callback is injected after the real process has launched. The two-dispatcher admission/recovery campaign retained in the existing budget suite exercises independent database connections, parent/child limits and recovery from unavailable scheduler observation.

Run at the release root with the configured Python interpreter.

```sh
PYTHONPATH=.:gx-h:gx-h/tests:acceptance/v62a GX_CODEX_OFFLINE=1 python -B -m unittest -v \
  acceptance.harness_final.jobs.test_shared_jobs \
  tests.test_v6_jobs tests.test_v6_prospective_jobs \
  acceptance.harness_refactor.budget.test_admission \
  acceptance.science_plugin_blueprint.test_recipe_binding
```

Two baseline regressions are retained for each release in `baselines.json` and the referenced logs. The six new tests exercise concurrent first admissions, simultaneous subscriptions with three separate delivered briefs, physical cancellation and cold recovery, driver-level reuse, a subsequent warm hit after the producer withdrew, isolated seats, explicit independent computation, and mismatched execution inputs. The digest checks for modified weight declarations and seed parameters use identity-layer fixtures. The CPU end-to-end tests use a pinned deterministic method. The tests leave existing historical runs and their evidence unchanged.
