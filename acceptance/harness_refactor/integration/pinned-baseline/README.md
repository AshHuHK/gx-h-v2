# 三批功能的隔離基線對照

同一組外部測例分別進入兩個臨時產品目錄。基線的 `bin`、`gx-h`、案例與舊測試夾具全部取自 Git 提交 `50d31f5792a178529a817ffd93f66ef9cbbb0be4`。候選使用本機產品快照與該提交的相同案例及舊夾具。兩份新測例的雜湊、參與比對的目錄、兩棵測試樹的內容摘要見 `comparison.json`。執行器會檢查載入的 GX 與測試模組皆位於受測樹內。臨時狀態與 Job 文件另存在測試樹旁的工作目錄。

| 批次 | 基線拒收原因 | 候選實際結果 |
| --- | --- | --- |
| 一 | 唯一方法與唯一同角色材料仍要求提交者填入 `inputs` | 從已授權的方法和同角色材料建成節點，保留精確版本及產物 ID。 |
| 二 | 有明確上游依賴的兩步 CPU 探針被要求先建立帶完整假設的分支 | 兩個 CPU Job 均執行。下游讀取上游的具名產物，兩次讀回均值 6；重送後仍只有兩個 Job。見 `two-jobs.json`。 |
| 三 | 回調只回傳通用主張格式錯誤，無法核對「方法正文已讀」這項具體等級 | 抽象摘要與無關結果段落均被擋，定位至方法正文後可發布。沒有模型 Job 的驗證等級也被擋，最後的主張回執保留正確正文摘要值。 |

三案基線 0/3、候選 3/3。每項基線失敗都須命中指定的業務拒收理由。原始回調由腳本驅動，模型費用為零。完整斷言與失敗位置在 `red.log`，成功日誌在 `green.log`。
