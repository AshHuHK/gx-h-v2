# GX-H 科研插件實施與複核

本次從完整研發分支 `science/multi-workflow@4759c260` 實作。驗收的單位是一次可追溯的科研行動。方法出現在清單、模型看過原文、GX 成功採用決策及外部計算成功各有不同的回執。下面的案號可以從結論往回追到入場材料。部署及回退請見[候選發行說明](DEPLOYMENT.md)。

## PI 給一個新問題之後會發生什麼

1. 從 `bin/gx-p0 research` 建立 Goal。PI 可以只給問題，也可以附原件及允許的能力集合。GX 在入場時凍結可啟用的方法。已有封存 Goal 沿用原範圍，包括顯式空清單。
2. 首回合 Lead 可同步調查背景並呼叫 `gx_query_catalog`。新版本首屏只顯示未啟用選項數；已授權的活躍工作仍有完整上下文。目錄回傳用途、提供者、具名輸入輸出、與本題輸出條件的差距、可否直接使用或啟用，並標出舊資料卡。遇同名提供者可以查精確版本。首次無命中仍可讀材料、拆題、補資料或說明未知。
3. Lead 可在既有範圍內啟用方法、從決策中派 Job，或把子問題交給研究員。有效輸入檢查、執行和恢復沿用 GX Job。最近執行狀態帶有部署、方法與環境範圍，24 小時為近況顯示窗口。學術來源回傳零篇、原件未取得與工具啟動故障分別記錄。
4. 新材料、子報告、Job 結果、相關 PI 變更或目錄變動會帶出新的研究上下文。Lead 可多次查詢；狀態及回執用於重送和冷恢復。同一輪後續改詞不需要另一個研究任務。研究者決定是否改變行動。
5. 深讀可採 `gx2understand@1`，用現有讀、摘、核工具追溯原始段落、端點、分母、樣本與限制；舊資產 `gx-understand@legacy` 仍可查閱。報告標明研究員原話和 GX 的 Job 事實。截短時保留全文入口。對重要衝突可委派另一個原生上下文讀同一原件，再把判斷送給 Lead。[閱讀技能驗收](test_reading_skill.py)
6. 配方保存已執行步驟的具名埠、版本及待裁決問題。後題重新綁定當前材料，從新讀數決定下一步。沿用已有校準須匹配材料、方法、環境及適用範圍。已發出的 Job 保留身份。歷史配方和人工發布來源均能分辨。[配方與換題驗收](recipes/README.md)

## 哪些重用已經過反例測試

兩個合法插件可以宣告相同方法內容而使用不同的輸入綁定程式。相同方法名和內容摘要不足以重用一次實驗。修後保存的配方會核對實際提供者與相依套件。當綁定器只負責輸入映射，而且實際輸入、參數及環境相同，既有校準可沿用。校準檔在排程後被替換，甚至在重啟之後才改，也不能拿舊 Job 的成果回答新問題。測試中的實際 CPU 任務在舊條件得均值 2，改變輸入後重算為 13；原始讀數完整保留。舊配方只能提供當時保存的身分保證。[配方複核、首次失敗與回歸](evidence/review-recipe.json)

科學重複、同一來源的另一份表示及恢復重送分別計算。B0 模型的首個有效坐標產物在開題後 555.925 秒落庫，該 Run 有 12 筆正式決策拒收與 2 個成功 Job。另有早期部署及真模型嘗試失敗，列在首次故障紀錄。B0 Lead 結題時沒有保存配方，平台組以 `gx_core.p0.v6_recipes.save` 從已完成的兩個 Job 發布 `archived-coordinate-agreement@1`，其作者和來源 Run 留在發布記錄。[B0 效率與分母](b0/metrics.json) · [配方發布回執](recipes/source-publication.json)
