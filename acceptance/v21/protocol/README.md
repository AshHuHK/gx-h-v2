# GX-H v2.1 native working-tree acceptance

All model endpoints in this directory are scripted HTTP Responses peers bound to 127.0.0.1. The official Codex CLI 0.169.0 starts an actual App Server subprocess, executes its normal protocol, and reports turn IDs, usage and terminal state. GX uses its actual SQLite database, leases, delivery path and budget owners. The detached Job cases launch a local CPU process. These probes do not measure production model quality or multi-hour wall-clock behavior.

| Evidence | Measurements |
| --- | --- |
| `routing.json` and baseline `native-wire.json` | Six exact opted-out notification names from production initialization. Streamed text generated three delta notifications in the native control and zero in production. Item/turn/token/raw/account notifications and one dynamic tool callback remained visible. The account reported 100% use. The active turn completed, a fresh task stayed READY at attempt zero, and a cold existing Root sent zero paid calls until the window reset. |
| `refusal.json` | Actual loopback HTTP 429 produced native `usageLimitExceeded` on the acknowledged worker turn. GX retained the lease and attempt, recorded zero agent or infrastructure failure settlements, refused a cold retry and allowed exactly one new turn on the original thread after reset. |
| `budget.json` | Two simultaneous native Root turns reserved 40 tokens each. The provider then reported 30 and 73 against a hard cap of 100. GX sent two interrupts and observed two original-turn interrupted terminals. The two confirmed charges total 103 and a further paid start was refused. The 3-token overshoot is observed for this run. The provider supplied no general upper bound. |
| `lease.json` | GX clock advanced to 300 seconds before the default lease expiry, then 150 seconds after it. Both real native tool callbacks obtained durable receipts on the same attempt and lease. |
| `cumulative-warm.json`, `cumulative-cold.json` | Throughout both cases Python GX could not open native rollout files. A turn with one receipt of 35 and a later receipt without usage was provisionally settled at 100 after grace. The next native cumulative was 70. Both cases recorded a single −65 correction and settled two calls at 70 total. The continuously attached Root retained a per-response receipt. After cold attach the official server only published cumulative usage and both turns have unknown individual attribution. Two identical cold deliveries reused one native turn ID with zero further provider requests. |
| `cumulative-incomplete.json` | A cold turn with two responses and an omitted final usage reported 70 twice. GX retained the hold, then provisionally estimated that turn. A later distinct cumulative of 105 reconciled both earlier estimates through two adjustment lines totalling −130. Repeating the delivery added no charge. |
| `child-no-rollout.json`, `child-missing.json` | With all GX rollout opens denied, a complete child receipt contributed 183 to its parent's 70 for one charge of 253. With the child usage omitted the separate turn cost remained unknown. After grace GX recorded the observed lower bound 70 and conservatively charged 100. The successor left the unresolved child estimate in place. |
| `child.json` | A native child continued after the parent's terminal. GX delayed the next turn until the correctly attributed cost was settled, then accepted one follow-up. |
| `wake-cold.json` | The relay killed GX immediately after the official App Server acknowledged the wake. The server completed the accepted turn. The fixture had already expired the original worker lease to model downtime. This early working-tree observation recovered one charge using the earlier rollout behavior. The frozen default-store run and its post-grace probe appear in the final evidence. |
| `incomplete-interrupt.json` | One raw usage receipt and two usage snapshots before an interruption. Warm and cold checks preserved the original unresolved reservation and withheld a successor during the tested pre-grace interval. |
| `official-suite/`, `retest/gx_job_wait.json` | The original pinned 17-case suite initially passed 16 cases and reproduced an inherited late-wake acknowledgment defect. After the exact read-only replay fix the remaining case passed from a fresh project. |
| `before-cold-checkpoint.json` | Earlier working-tree reproduction of missing aggregate correction after cold attach. The later cold and warm reports above exercise the correction. |

Run `python -B acceptance/v21/regression.py --commit <candidate> --native --out <output>` from the source repository to run Python, host generation, Node and all native scenarios against a release commit. The binary and experimental schema hashes are checked locally. The native setup handles the provider peer and temporary native state. The raw Responses request body and HTTP authorization fields do not enter the reports.
