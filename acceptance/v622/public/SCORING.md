# Public coverage adjudication, series 02

For a complete registered offline batch, run the following commands from the release root. Use a fresh output directory outside the original batch. The first command seals the opportunity packet and lock for every original assignment. The second command verifies those files before it reads the endpoint key and adjudicates the first decision window.

```bash
.venv/bin/python -B acceptance/v622/public/rate.py --work "$GX_RESULT_DIR" --output "$GX_RERATE_DIR" --stage opportunity
.venv/bin/python -B acceptance/v622/public/rate.py --work "$GX_RESULT_DIR" --output "$GX_RERATE_DIR" --stage outcome
```

The first reader receives the opening plan and the qualifying numeric values in delivery order. Closed, timed-out, missing and unused-delegation assignments retain their enrolled slots. An index alone exposes no measurement. A successful original tool return may supply the measurement when the native conversation shows delivery before the decision. Module evidence must come from the commissioned worker's authorized Job and publication. A newly opened module can receive its first task in the transaction that creates its grant. Its parent native opening, assignment, first task, context and later Job admission must agree.

The independent parser reads the assigned mmCIF bytes in the original artifact store, checks the pinned SHA and counts the residues again with Biopython. The endpoint comparison uses the exact fraction. Each score records the first window, scientific rationale, enacted effect, citation, formal numeric evidence, delegation and observed usage. A completed reference Job with the registered input and atom selection remains the original comparison even if given a new branch or node name. A justified branch withdrawal or scoped early close can change the plan without a follow-up Job. A job dispatched automatically after a cited no-op supplies no enacted decision. The source and decision receipts remain available in the outcome packet and causal trace.

The scripted adjudicator recognizes the registered public comparison and explicit coverage explanations in these offline conversations. Unknown plans or ambiguous explanations receive no positive credit. The results establish the tested receipt chain and deterministic challenge cases. A real-model evaluation requires an independently authorized and registered rating process. The output leaves provider tokens and dollar cost unknown where a real provider receipt does not exist.
