# V6.2C public evidence-to-action pilot

The public study tests whether a Lead acts on a prospective coordinate completeness result. Its four slots cross a withdrawal or maintenance opportunity with a single Lead or a Lead offered one pinned research module. Both arms use deep research policy, the same source files and measurement definition, and the same local CPU capability. No arm has legacy branch-agent delegation. The scripted investigator chooses whether to use the offered module according to its script. Live participants may take the direct route in either arm.

## Reproduce the offline experiment

Run from the candidate checkout with its installed Python environment, Biopython, fixed official Codex binary and the local Clash binary. Choose a fresh result directory outside the checkout. The launcher starts a reject-only private loopback network, saves each isolated GX state and locks the opportunity assessment before outcome scoring. The official Codex host sends requests only to the local scripted Responses provider.

```bash
bash acceptance/v62c/run-public.sh /tmp/gx-public-coverage-work /absolute/path/to/clash.new
.venv/bin/python -B acceptance/v62c/spending.py --require-paid-ready
```

The second command is an offline paid-readiness probe. Exit 2 records a held gate. It has no enrollment side effects. Four public live slots and both historical private slots initially remain unused.

The launcher writes the protocol, runtime file hashes, registered material digests, model and grant into `run/registration.json` and `run/runtime-pins.json` before starting the first official host. A single-slot development probe uses `rehearse.py --slot NN` inside the same local network, with a fresh directory. Each such probe is separate from the four formal scripted slots.

## Materials and decisions

Both files are deterministic copies of the same deposited archive, with selected coordinate observations withheld. The specimen keeps its sequence and the recorded coordinates of retained atoms. Parent source metadata and the exact transform are in `materials.py`. The product pins and acquires the parent, then prospectively assigns the derivative by digest after the first accepted global Lead decision. The specimen is named `assigned-specimen` in every Run. No case or architecture label, expected decision or independent result is added to the delivered material. The operator's assignment map and independently parsed numerical endpoint stay outside the hosted workspace.

The endpoint is the number of complete shared backbone positions divided by the union of observed positions across the three registered chains. The action threshold in the common method card is three fifths. Insufficient coverage makes the original backbone comparison inapplicable. A concordant decision withdraws or narrows that route and enacts the change. Adequate coverage warrants a reasoned continuation and an executed reference measurement. Neither file establishes independent biological samples.

Each slot includes an accepted provisional plan, operator acquisition, a real GX-supervised local measurement, the actual subsequent native Lead brief and action, a formally published measured claim, and cold terminal replay. Both grants allow the same method catalog and source reads. The parity check uses actual native callbacks and canonical card contents. The module path also replays an original terminal callback twice to verify idempotent delivery. Development probes and any transport faults retain their original identities.

## Read the receipts

- `run/result.json` records execution, nominal resources, zero paid calls, local fixture use by actor, and wall time. Every individual Run retains its state, signed-by-content artifact inventory, official session JSONL and CLI/wire transcripts.
- `run/ratings/NN/opportunity-lock.json` freezes the first packet with the matching Job, method, role, assigned digest and measurement before exposing later decisions. The second-stage reader judges actions; native report and delivery receipts establish any delegation credit. Architecture can remain inferable from report structure. Scripted reviews demonstrate scoring behavior.
- `run/scores.json` reports all assigned slots, including unused delegation and withheld credit. `run/capability-parity.json` compares the normalized native menus, physically read cards, data, CPU Jobs, and per-material cost differences. Local fixture token totals describe the engineering exercise. Live provider tokens, cache, prices and dollars await provider settlement.

## Live and private handoff

Public series `GX-V62C-PUBLIC-COVERAGE-01` has four assignments, one enrollment per assignment and no replacement after a timeout, error or non-use. Its proposed caps are 1,000,000 tokens per slot and 4,000,000 for the complete batch including all descendants and unresolved requests. Its production gate requires exact authorization and an enforceable atomic upper bound on every potential billable request in both scopes. Stop on source mismatch, leakage, unsupported scientific support, unauthorized work or irreconcilable usage. The scorer accepts live scientific behavior only with actual official host/provider evidence.

The historical private series is `V62B-UNSEEN-PAIR-01` at 0/2. Runtime, primary scoring, acquisition and available arms have changed. A successor requires an independent custodian to link both protocol versions, confirm materials are still unseen, preregister independent readers and obtain separate authority before enrollment. No private material or private denominator is touched by this public exercise. Hold V6.3 research validation until there is a live change and maintenance comparison and a verifiable live delegation chain; these four public slots cannot estimate reliability or cost superiority.
