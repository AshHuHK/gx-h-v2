## 压缩、重启与原生子 Agent（源码审计）

OpenAI 和 Azure Responses 的缺省远程压缩能力是 v2，一般自定义 provider 缺省 unsupported，配置可覆盖。这里 unsupported 是远程压缩能力；在普通手动压缩路径会改为用配置的 Responses 模型请求 summary，然后重建上下文。锁定版本的 wire API 接受 Responses。远程 v2 与本地路径都会装入新的上下文窗口，普通开发者指令来自当时实际生效的 turn 配置。把 wake packet 仅放在一次普通 user 输入中时，摘要可能缩短该输入；GX 可从数据库重新构造任务书。[provider 能力](../vendor/codex/codex-rs/model-provider/src/capabilities.rs#L34) · [wire API](../vendor/codex/codex-rs/model-provider-info/src/lib.rs#L117) · [手动分流](../vendor/codex/codex-rs/core/src/tasks/compact.rs#L63) · [本地重建](../vendor/codex/codex-rs/core/src/compact.rs#L431) · [远程安装](../vendor/codex/codex-rs/core/src/compact_remote_v2_installation.rs#L209) · [开发者指令](../vendor/codex/codex-rs/core/src/session/mod.rs#L5127)

冷 resume 从已存储的历史恢复，包括有效的 compaction replacement history；已运行 thread 的 override 限制见上表。恢复所用 provider 同时受保存设置和当前管理策略校验。原生 V2 fork 处理父历史、role 与 `subagent_developer_instructions`，子线程有效任务指令可能与父指令不同。上游有压缩后 full-history fork、worker cold-resume 的测试定义。测试定义和源码分支只能支持边界分析，普通 OpenAI、指定真实第三方、fork 及 resume 的交叉组合需查看实际请求或模型结果。[历史重建](../vendor/codex/codex-rs/core/src/session/rollout_reconstruction.rs#L526) · [provider 校验](../vendor/codex/codex-rs/app-server/src/config_manager.rs#L521) · [父子指令选择](../vendor/codex/codex-rs/core/src/agent/history.rs#L188) · [已压缩 fork 测试](../vendor/codex/codex-rs/app-server/tests/suite/v2/multi_agent_v2_developer_instructions.rs#L295) · [冷恢复测试](../vendor/codex/codex-rs/app-server/tests/suite/v2/multi_agent_v2_developer_instructions.rs#L520)
